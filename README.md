# 점심 빙고

회사 앞에서 **점심에 문 여는 매출 상위 24곳**으로 5×5 빙고판을 만들어 주는 작은 웹 서비스입니다.
한 곳 갈 때마다 도장 하나, 가로·세로·대각선 한 줄이면 빙고. 같은 동네 동료는 그달 같은 판을 받고, 내 판을 링크로 보내 진행 상황을 겨룰 수 있습니다.

<https://indosaram.github.io/lunch-bingo/>

## 데이터

- [k-skill 잇플 스킬 `bccard-eatpl-search`](https://github.com/NomaDamas/k-skill/tree/main/bccard-eatpl-search)의 검색 API(k-skill-proxy 경유)를 동네별 도로명·법정동으로 호출합니다 (`areas.json`). 검색은 연속된 주소 부분 일치이므로 도로명 주소 뒤 괄호의 법정동도 찾도록 기존 질의를 유지하고, 응답 주소의 시/도·시/구를 `localities`와 대조합니다. 예를 들어 잠실은 서울 송파구만 포함하며 대구·시흥의 신천동은 제외합니다. 반경/도보 거리 검색은 아닙니다.
- 카페·주점·베이커리를 빼고, 결제 시각으로 추정한 영업시간이 11:30–13:30을 포함하는 곳만 남긴 뒤 전국 매출 백분위 순 상위 24곳을 고릅니다 (`build.py`).
- 매달 첫 빌드에서 상위 24곳을 선택하고 `(동네, 월)` 시드로 배치합니다. 이후에는 현재 게시된 판의 매장·위치를 유지하므로 25위 매장이 올라와도 월중 판이 바뀌지 않습니다. 지역 밖 주소, 제외 업종, 현재 응답에서 확인된 점심시간 미충족은 해당 칸만 교체합니다.
- GitHub Actions가 매일 05:30 KST에 표시 데이터를 갱신합니다. 기존 매장이 검색 결과에서 빠졌다는 이유만으로 폐업으로 간주하지 않습니다. 검색 결과 수 제한으로 빠진 매장은 마지막 표시 값을 유지하고, 상세 화면에 그 매장의 실제 갱신일을 표시합니다.
- 빌드는 기존 `site/data/` 또는 현재 배포 사이트의 JSON만 참고합니다. 기존 판을 읽지 못하거나 검증된 식당 24곳을 확보하지 못하면 실패하며 일부 동네를 조용히 삭제하지 않습니다. **원본 API 응답을 저장하거나 누적하지 않고**, 현재 화면에 표시할 값만 빌드 산출물에 담습니다.

## 도장 저장

- 도장은 기기 안의 `localStorage`에 `(월, 동네)`별로 저장됩니다. 새 달은 새 도장으로 시작하고, 같은 달 판의 수정에서는 같은 매장 URL의 도장을 유지합니다. 다른 동네에는 자동으로 도장을 복사하지 않습니다.
- 이전 `lunchbingo:v1` 데이터는 삭제하거나 덮어쓰지 않습니다. 기존 데이터는 매장별 동네 정보가 없어, 각 동네의 첫 이관 때 해당 월의 유효한 방문 기록을 모두 옮겨 과거 전역 URL 저장 방식을 보존합니다. 현재 판에 없는 매장의 도장은 집계하지 않지만, 같은 달 판 수정으로 매장이 돌아오면 복원할 수 있습니다. 옮긴 뒤 지운 도장을 다시 가져오지 않습니다.

## 로컬 검증·빌드

별도 패키지 설치 없이 Python 3.12와 Node.js 22 이상에서 실행할 수 있습니다.

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
node --check src/app.js
node --test tests/test_app.cjs
```

테스트는 합성 데이터와 모의 네트워크만 사용하며 API나 상세 페이지를 호출하지 않습니다. 실제 빌드는 검색 API와 현재 배포 JSON을 읽습니다.

```sh
python3 build.py             # 모든 동네
python3 build.py jamsil      # 지정한 동네만 포함하는 로컬 산출물
```

`EATPL_PREVIOUS_SITE`의 기본값은 현재 배포 주소입니다. 새 사이트의 첫 빌드처럼 기존 판이 없는 경우에만 빈 값으로 설정할 수 있습니다. 같은 달 재배포에서 기존 판 읽기를 끄면 월중 고정이 깨질 수 있습니다. 기존 공개 판과 호환하려고 `month`가 없으면 `updated`의 연월을 사용하며, 새 판 식별자는 월도 포함합니다.

## 잇플 연결

- 상세 링크는 API가 준 `merUrl`을 **변형 없이** `<a href target="_blank" rel="noopener">`로 엽니다 (`noreferrer` 없음, 추적 파라미터·단축 URL·중간 페이지 없음).
- `<meta name="referrer" content="strict-origin-when-cross-origin">` — 잇플에는 `https://indosaram.github.io/`가 유입 경로로 전달됩니다.
- 서버(빌드)는 검색 API만 호출하고 상세 페이지는 호출하지 않습니다.
